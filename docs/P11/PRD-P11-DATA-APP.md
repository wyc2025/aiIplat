## 1. 背景与目标

P7 内容池让用户「按站发表」，但数据模型是平台写死的（文章/栏目/标签/评论）。本期把「数据管理」本身产品化：用户经 **AI 对话或空白表单**创建**数据应用**（自定义逻辑表 + 字段 + 关系），平台**自动生成管理后台（功能页）**供其管理数据，数据全部落在沙箱化的元模型存储里（D87）。博客 = 第一个类比样板（4 表 + 功能页），但本平台不为博客服务——任何「表 + 关系 + 数据管理」类应用（相册、书单、记账、库存）都应能建。

**本期只做 A 全链**：应用中心菜单、应用 CRUD、表/字段/关系结构管理、功能页（多表编排）、数据 CRUD、CSV 导入导出、附件字段、AI 创建工具组。展示应用 B（P12）、应用市场（P13）、AI agent 类应用与创建 agent 化（P14，§10.1 挂账）均不在本期。

## 2. 决策

- **D87 元模型 + JSON 行**（沿用，本期落地）：用户表只是逻辑表，落 app 域 8 张真实表，数据集中 app_record JSON 列；真实动态建表一票否决（击穿 Prisma 迁移/备份/沙箱）。
- **D88 与 site 域共存不迁移**（沿用）：站点/博客保持原生；本期博客仅作验收样板场景。
- **D91 渲染承载**（沿用）：功能页 = 主应用路由渲染（AdminRenderer，平台组件渲染模式 JSON，不执行用户代码）；不引入微前端/iframe（评估见盘点 §10.2）。
- **D92 菜单功能导向**（用户 2026-09-22 拍板，推翻线框案 A/B）：菜单 = 应用中心 ▸ 应用 ▸ **功能页**；不按表挂菜单。功能页是多表编排单元（「新增文章」= 写 article + 读 column/tag）。
- **D93 P11 范围 = A 全链**：B（绑定/多页/公开）→ P12，市场（发布/审核/复制）→ P13。P11 不为 B 预留任何端点，app_binding/app_pub_code 等列本期不建（ARCHITECTURE §1 表清单为准，少建比多建好撤回）。
- **D94 数据出口对称**（Kimi 拍板，可驳回）：导入导出同为 CSV v1 都做——只进不出 = 平台扣押数据观感，对称实现成本极低。
- **D95 结构变更软着陆**（G3）：字段删除 = 软删（is_deleted），数据保留；字段类型收窄（如 text→enum）先跑存量数据校验，不合规阻断并提示；加字段/加表随时允许。不做物理删列。
- **D96 附件落云盘专用目录 + 引用预检**（G6）：附件字段 = 上传到 cloud 专用目录 `/app-attachments/{appCode}/`（占云盘配额）；cloud 删除链路加预检——被应用数据引用的文件禁止删除（新码 30021），方向 cloud→app 经 AppFacade.getAttachmentRefs（对称 Facade，防 SiteFacade→CloudFacade 式循环，照 P4d 先例）。

## 3. 规则

- **R88 字段类型七类**：text / number / datetime / bool / enum / attachment / ref。富文本、公式、自动编号后置（正文用 Markdown 文本，规避富文本消毒依赖）；enum 选项表内定义（enum_options JSON）。
- **R89 关系模型**：一对多（ref 字段即 1n 的 n 侧）+ 多对多（中间表平台**自动生成**、is_system=1 用户不可见；用户只看到「article 多对多 tag」）。
- **R90 功能页多表编排 + 事务**（G4）：功能页 schema 声明多个数据源（读）与动作（写）；一次动作含多表写时必须整体成功或整体回滚（沙箱数据服务以真实库事务包裹）。
- **R91 草稿生命周期**（G2）：AI 创建先落 draft 态应用（不入册、不占配额主额度——草稿 ≤3 个/用户），用户确认后转 active；草稿 7 天未确认自动清理（任务调度，照回收站清理先例）。
- **R92 CSV 导入导出**（G5/Q5）：导入 = CSV 一种，列名自动映射 + 人工确认 + 前 5 行预览 + 错误行报告（不中断，成功行落库）；单文件 ≤5MB；解析自研（CSV 格式简单，引依赖要特批不值）；导出 = 全表 CSV（≤5 万行，超出截断提示）。
- **R93 code 双轨唯一**（G1）：应用 code = 用户内唯一（slug 化名称 + 冲突 "(1)"）；pub_code = 全局唯一 12 位随机串（字母数字，**本期不公开使用**，P12 公开访问才启用；先建先唯一，避免 P12 返工）。
- **R94 校验双道**：所有入口（人工表单 + AI 工具）同一份 zod/class-validator 校验链；AI 生成的表结构/功能页 schema 落库前必须过校验，不过 = 拒绝并回喂可读原因（不静默丢弃）。
- **R95 查询白名单**：沙箱数据服务只接受枚举操作——list（eq/ne/gt/gte/lt/lte/contains/in + 多字段排序 + 分页）/ get / count / create / update / delete（软删）；ref 展开 ≤1 层；禁止任意 JOIN、禁止裸 SQL 到用户数据（应用层解析逻辑表）。
- **R96 动态菜单口径**：sys_menu 种子只加「应用中心」一级（common 角色可见）；其子菜单由后端按用户 active 应用 + 功能页追加进 userinfo.menus 动态段（前端拼树）；层级 ≤3；应用删除菜单即消（W1 教训的正面利用：动态段零种子依赖）。
- **R97 功能页 AI 生成可改**（Q2）：功能页 schema 生成后允许人工编辑（可视化表单改区块/字段绑定），AI 调整为并列入口。
- **R98 AI 工具组手册预算**（G12）：新增 app 组 7 工具，手册改动量 = 通用版 ≤20 字 + 能力清单 ≤368 字（当前余量 980/1000、832/1200，按 P10 走查报告 §五更新），超了先精简既有条目（P10 已示范等量腾挪）；**改工具链必跑 check:ai + smoke:ai**（T95 制度），smoke 新增 **L 用例**。
- **R99 性能护栏**：列表强制分页（默认 20/上限 100）；单查询 >2s 拒绝（提示缩小范围）；schema 全量走 Redis 缓存（`app:schema:{appId}`，结构变更即失效）；导入异步任务 + 进度轮询。

## 5. 验收标准

1. **空白创建**：表单建「书单」应用（book 表：书名/作者/评分/读完日期）→ 应用中心出现，菜单出现「书单 ▸ 书单管理」功能页（AI 生成），可增删改查；
2. **AI 创建**：对话「我要一个博客系统：文章/栏目/标签/评论，评论要审核」→ AI 追问 ≤2 轮后生成 4 表草案 → 确认入册 → 功能页自动生成 ≥3 个（文章管理/新增文章/评论审核）；smoke:ai **L 用例**：`ai_tool_call` 落库 app 组工具调用且 app_def/app_table 落库；
3. **多表编排**：「新增文章」功能页打开即载栏目下拉 + 标签多选（读 column/tag），提交写 article 成功；
4. **事务**：构造功能页双写动作（demo：评论通过时同时更新文章计数列）中途失败 → 两表均无残数据（测试脚本断言）；
5. **结构变更**：加字段即时生效；删字段软删且历史数据保留；text→enum 收窄遇不合规存量 → 50003 阻断并给出行号清单；
6. **导入导出**：CSV 导入 100 行含 3 行错误 → 97 行落库 + 错误报告；导出 CSV 与库内数据一致；
7. **校验链**：他人应用 50001、超配额 50002（message 带配额项）、类型白名单外字段 50005、AI 生成非法 schema 50004；
8. **草稿**：AI 创建未确认 = draft 不入册不占 active 额度；7 天清理任务可手动触发验证；
9. **附件**：附件字段上传落 `/app-attachments/{appCode}/`、云盘配额记账；删除该云盘文件 → 30021 阻断；
10. **菜单**：应用删除后其动态菜单段即时消失；common 角色可见「应用中心」，无 app:* 管理标识也能全权管理自己的应用（属主校验兜底）；
11. **回归**：check:ai 全绿（断言数随 app 组增加，以脚本输出为准）；smoke:ai F/I/J/K 不回归 + L 通过；无应用功能的旧对话零变化；
12. **手册**：通用版 ≤1000、能力清单 ≤1200、合注 ≤2000 全过；实测消耗积分如实登记。
