# PRD-P12-PATCH1：R97 可视化页编辑器

> 状态：待实施，**随 P12 同一窗口执行**（挂 P12 任务表 T115）。
> 来源：P11 走查遗留第 2 项——用户 2026-09-23 裁定「功能页编辑器 JSON 文本编辑现状不接受」，按走查补丁立项。
> 编号：D105 / R109~R113 / T115。**纯前端补丁：零新依赖、零后端改动、零新错误码、零新 AI 工具**。

## 1. 背景与问题

P11 的 R97 原规格为「可视化表单改区块/字段绑定」，落地时 CodeBuddy 按当时口径实现为「列表 + 新建（模板预填）+ JSON 文本编辑 + 删除」（PROGRESS 遗留第 1 条已声明）。P11 走查时我方给出「接受现状 / 要求补丁」二选一的待拍板项，**用户裁定：不接受现状，出补丁**。

问题本质：功能页 schema（layout/dataSources/actions 三段 JSON）让非技术用户手写不现实，AI 生成后又没有低门槛的微调手段——「AI 建草稿 + 人工微调」闭环缺了后半截。

## 2. 决策

- **D105 补丁范围与形态**：功能页**可视化编辑器**——区块编排 + 区块/数据源/动作表单化配置；**admin 与 display 两类页通吃**（P12 已引入 display kind，编辑器直接覆盖）。纯前端实现：
  - **后端零改动**：保存仍走既有 `PUT /api/app/:code/pages/:pid`，50004 带路径校验复用；
  - **零新依赖**：区块排序用「上移/下移」按钮，**不引拖拽库**（若将来要拖拽手感，另行提请铁律 7 特批）；
  - JSON 文本编辑**降级保留**为「高级模式」标签页，不删除（AI 生成内容的兜底逃生门）。

## 3. 规则

- **R109 编辑器形态**：页编辑器行级「编辑」打开编辑窗，默认**可视化标签页**；「高级模式」（JSON）标签页保留。两模式各存各稿、不实时互转；切换标签时以**库中最新保存版本**重新载入，杜绝双向同步歧义。
- **R110 区块编排**：增（选块：admin 四型 filterBar/table/form/detail；display 三型 filterBar/table/detail）、删、**上移/下移**排序；每区块配置 = bind 数据源（下拉）+ 类型化表单（见 R111/R112）。
- **R111 字段选择器**：选项取自既有 `GET /api/app/:code/schema` 全量打包（含 Redis 缓存，零新端点）；按字段类型出算子/控件——text→contains/eq + 输入框；number/date→比较符全集；enum→eq + 下拉（选项来自 enum_options）；ref→目标表选择 + 单/多选（照 ref_multiple）；attachment→上传控件（走既有 `/app/:code/attachment`）；`rowId` 内置列放行（P11 先例）。列/表单/详情/筛选四类字段列表均可增删排序，**字段 DSL 由编辑器生成**，用户不手写 `字段:op` 语法。
- **R112 数据源与动作编排**：dataSources 表单化（op/table/sort/size/fields；display 页仅 list/get 可选）；admin 页 actions 步骤编排（步骤增删、每步 op/table、tx 开关，多表编排 params 子对象结构照 ARCHITECTURE §27.5）；display 页 table 区块的 **rowLink** 目标页下拉（限同应用内 display 页）+ rowIdParam 可改（默认 `rowId`）。
- **R113 保存与校验反馈**：提交同一 schema JSON 走既有 PUT（契约零改动）；50004 错误按 path 就地展示（错误路径高亮 + message，字段级定位尽力而为）；保存成功后提示可前往功能页/公开页查看。

## 4. 预览（只读，草稿态）

- 编辑窗内「预览」= **只读渲染草稿 schema**：filterBar/table/detail 区块经既有 AdminRenderer/PublicRenderer 组件直接渲染，数据源当场走 `POST /api/app/data/query`（DSL 直查，与页 schema 是否已保存无关）拉真实数据。
- **form 区块禁用提交**（不渲染动作按钮）；动作（actions）不在预览中执行。
- 预览不落地任何数据，不产生写请求。
