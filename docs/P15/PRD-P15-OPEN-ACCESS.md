## 1. 背景

P14 已把「对外取数」从匿名公开窗修订为授权取数面（数据应用 → `disp_grant` 授权 → 展示应用 → 挂靠站点），但交付后澄清两处边界：① 授权粒度止于站点（同站点下未授权的展示应用也能调同一接口）；② 匿名层无凭证、不可管控（语义实为「该站点公开可读」）。叠加两个新场景——**对外开放给特定外部系统取数**、**AI MCP 能力**——调用方都不是匿名公众，必须回答「谁在调、能读什么、读了多少、如何停掉」。

本期把对外访问从「站点 = 唯一隐式主体」升级为「**多主体 + 凭证 + 范围授权 + 配额 + 审计**」的统一接入层。分治原则（立项建议 §2.3，拍板确认）：**匿名层只表达「公开数据」，管控型访问一律走凭证**。

## 3. 范围

### 3.1 本期做

**A 部分（地基收敛）：**

1. 授权判定主体化：`DisplayFacade.assertCanRead(appId, principal)`，`principal ∈ {display, credential}`（A 期先落地 display；credential 随 B 部分接入）。**site 主体不实现**——Q6(a) 拍板后旧站点级路径退役，site 反查失去存在意义（A+B 合期红利：不做一次性过渡品）。
2. 开放层取数路径收窄（D123），旧路径退役。
3. 审计埋点：匿名层取数（display 主体）与凭证层取数统一入 `acc_audit`。

**B 部分（外部系统接入，新域 `access`）：** 4. `acc_credential` / `acc_audit` 两表 + 凭证生命周期（创建 / 吊销 / 轮换 / 过期 / 校验链）。5. 对外取数端点 `/api/ext/v1/app/:appCode/**` 四端点，与开放层同构、走同一 `AppFacade` 取数管道。6. 按 principal 配额（请求数 + 行数，日/分双窗）。7. 对外契约版本化 + 游标分页（外部系统全量拉取用 offset 会漏行）。8. 后管管理面：凭证列表 / 新建（secret 仅展示一次）/ 吊销 / 轮换 / scope 编辑 / 用量与审计查看。

### 3.2 本期不做（非目标）

- 对外写数据（D119）；按量计费与账单；跨属主授权（D127）；行级 `rowFilter` 实现（仅预留）；MCP 适配器（下期）；凭证的市场分发（市场 bundle 不带对外凭证，沿用 P14 §30.6 口径）；匿名层 token 化（Q6-b 未采纳）；OAuth client_credentials（D120 预留）。
- **不给 AI 加凭证管理工具**：secret 仅创建时展示一次，AI 对话不是安全通道（R140）；AI 工具链的改动仅限文案（取数路径随 D123 改）。

## 4. 需求详述（规则）

### 4.1 凭证模型（R130）

- Key 字符串形态：`{keyId}.{secret}`——`keyId` = `ik_` + 10 位 base62（定位索引用）；`secret` = 32 字节随机 base64url（43 字符）。
- 存储：`secret_hash = sha256(secret)`（高熵随机无需盐/bcrypt——高频校验场景 bcrypt 成本不可接受，彩虹表对 256bit 随机无意义）；列表/详情只回显 `keyId + secret 前 4 位`。
- **secret 仅在创建（与轮换）响应中出现一次**，此后任何端点不返回；创建响应必须带醒目提示文案键 `secretOnce: true`。
- 状态机：`active → revoked`（吊销不可逆）；`expiresAt` 到点即失效（惰性判定，无 cron）；另有 `lastUsedAt` 每次命中更新（异步，允许分钟级延迟）。
- 每用户凭证数上限 `access.maxCredentialsPerUser`（默认 20），超限 50020。

### 4.2 凭证生命周期（R131）

- 创建：选应用（自己名下、未软删的数据应用）+ scope（表/字段子集）+ 可选过期时间 + 备注名。
- 吊销：立即生效（凭证校验**不缓存**，每次实查 DB——撤权时效沿用 P14「实查」口径，代价由调用频次上限兜住）。
- 轮换：生成新 secret（旧 secret **立即失效**，无双活窗口——v1 简化，双活记演进预留），keyId 不变、审计连续性保持。
- 管理侧端点全部要求登录 + 属主校验（非属主 50001 口径），自服务无 `@RequirePermission`（照 P14 display 先例）。

### 4.3 对外取数校验链（R132）

`GET /api/ext/v1/app/:appCode/**` 四端点（schema / records / records/:rowId / files/:f/stream），统一判定序：

1. **凭证**：`Authorization: Bearer {keyId}.{secret}`——缺失 / keyId 不存在 / hash 不匹配 / 已吊销 / 已过期 → **HTTP 401 + `WWW-Authenticate: Bearer`**，body 统一体 `code=50019`（对外开发者语义清晰优先于防探测；这是凭证层与匿名层的刻意差异）；
2. **应用匹配**：凭证 `app_id` 对应的 `appCode` ≠ 路径 `:appCode` → 40400（不暴露应用存在性）；
3. **属主与总开关**：应用未软删且 `is_public = 1` → 否则 40400；
4. **scope 收窄**：请求表/字段 ∈ `scope ∩ 暴露三开关`——表不在 scope 或表/字段未暴露 → 40400；schema 投影只输出交集（越权即不可见，不报错）；
5. **配额**：超限 → **HTTP 429 + `code=42900`**（带 `Retry-After`）；
6. 参数校验失败 → 40001（沿用）。

### 4.4 scope 语义（R133，落实 D125）

- `scope.tables`：可读的表名清单（空数组 = 无任何表，创建时禁止为空 → 40001）。
- `scope.fields`：`{tableName: [fieldName…]}`，缺省的表 = 该表全部已暴露字段。
- **只能收窄**：保存时逐项校验 ⊆ 暴露三开关并集，越界 → **50021**（显式报错优于静默收窄）；运行时再取交集（暴露开关后续收紧时凭证自动跟着收窄，无需改凭证）。
- `ops` 固定 `["read"]`；`rowFilter` 列预留（NULL），本期不实现。

### 4.5 配额（R134，落实 D121）

- 双窗：请求数 `access.quotaPerMinute`（默认 120/分）+ `access.quotaPerDay`（默认 50,000/日）；行数 `access.rowsPerDay`（默认 100,000/日，**按返回行数累计**；schema 端点计 0 行）。
- 实现：Redis 计数器（Key 见 API 增补），窗口首写设 TTL；超限 HTTP 429 + 42900。
- 匿名层既有 60 次/分/IP 限流**保留不动**（防爬，与凭证配额是两层）。

### 4.6 审计（R135，落实 D122）

- `acc_audit` 字段：principal（`display:{id}` / `cred:{id}`）、ownerId、appId、endpoint、tableName、paramsSummary（截断 ≤512 字符）、rows（返回行数）、durationMs、ip、resultCode、createdAt。
- **异步落表**：内存缓冲队列，批量插入（每 5s 或满 100 条 flush），进程退出前 drain；写库失败只记日志不阻断取数。
- 覆盖范围：开放层取数（display 主体）+ 对外取数（credential 主体）**都记**——匿名层同样需要「谁在读」的观测面。
- 保留 90 天：`access-clean.task.ts` 每日清理（沿用 recycle-clean 的分批幂等模式）。
- 检索端点：按凭证 / 时间范围 / 结果码过滤，分页（属主只能看自己的）。

### 4.7 对外契约 v1（R136，落实 D124）

- 前缀 `/api/ext/v1/`；**v1 冻结**：只增不改，破坏性变更开 v2。
- envelope：`{ data, paging: { nextCursor: string|null, size: number } }`（records 列表）；schema / detail / stream 形状见 API 增补。**不直接透传内部响应形状**（内部 `{list,total,pageNo}` 不出域）。
- **游标分页**：列表只收 `after`（cursor）+ `size`（≤50 沿用 R104）；排序默认 `rowId` 升序（稳定）；`sort` 白名单字段允许但服务端自动追加 `rowId` tiebreaker；**不提供 pageNo/offset**。
- 行数据字段名 = 用户定义的逻辑字段名（`app_field.name`）；内部实现列（`r_cN` 等）经既有白名单投影本就不出域。

### 4.8 开放层路径收窄（R137，落实 D123）

- 新取数路径（**唯一**）：`GET /api/open/:slug/disp/:id/api/app/:appCode/{schema|tables/:t/records|tables/:t/records/:rowId|files/:f/stream}`。
- 校验链 R125 修订：站点存在 → **该 `displayId` 存在、未软删、且挂靠该站点** → `disp_grant(displayId, appId)` 命中 → `is_public=1` → 暴露三开关；任一不满足 40400。粒度由站点级收窄为展示应用级（同站点其他展示应用不再能调）。
- 旧路径 `:slug/api/app/:appCode/**`（P14 四端点）**退役**：控制器移除，访问 404（照 §21 退役先例）。
- **路由吞并双保险**：新数据控制器声明在 `:slug/disp/:id/**` 静态通配**之前**（§30.3 已证明顺序错了会被吞成首页 200）；且静态处理器对 `disp/:id/api/` 子前缀路径直接 40400（不落入文件解析）。
- R124 生成规范修订：展示应用页面取数改**同源相对路径** `./api/app/<appCode>/...`（页面位于 `disp/{id}/`，天然同源）；站点 README 三模板「数据应用取数」节重写；`create_display_app` / `authorize_data_app` 的 nextSteps 与文案同步改。
- **存量迁移**：P14 与本期间隔极短，存量已生成展示页面按「预期破坏窗口」处理——用户重新生成/手改取数路径；PRD 发布时明示。

### 4.9 判定主体化与单一管道（R138 / R139）

- `DisplayFacade.assertCanRead(appId, principal)`：`principal.type = 'display'` 查 `disp_grant`；`'credential'` 走 R132 链。site 形态不实现（见 §3.1-1）。
- **取数仍只经 `AppFacade` 现有方法**（`resolveGrantedApp` / `publicSchema` / `publicList` / `publicDetail` / `publicAttachment`），新接入只是多一个调用方；**绝不新开直读表的通道**。scope 交集在 access 域内完成（表/字段名过滤参数下传），AppFacade 不需要认识凭证。

### 4.10 凭证与 AI 隔离（R140）

不新增任何凭证管理 AI 工具；secret 不进对话、不进 `ai_tool_call` 留痕；AI 文案只教「去应用中心 ▸ 接入凭证页面操作」。AI 链路的唯一改动 = D123 的取数路径文案 → 属工具链变更，**必跑 `pnpm smoke:ai`**（M/O 用例口径同步）。

### 4.11 横切纪律（R141）

配额与审计在 access 域的守卫/拦截器层各做一次（凭证解析结果塞 request 上下文，拦截器统一记账）；开放层匿名取数的审计经 `AccessFacade.writeAudit`（唯一的跨域消费点，异步不阻断）。禁止在四端点各自实现一套。

## 6. 验收标准

1. 模拟第三方系统以 Key 经 `/api/ext/v1/**` 取到数（schema / 列表游标翻页 / 详情 / 附件流四端点各一正例）。
2. 凭证吊销 / 过期 / 轮换后旧 secret：**立即** HTTP 401 + `WWW-Authenticate`；错误计数入审计。
3. 越权：scope 外表 → 40400；scope 内但未暴露的表/字段 → schema 不可见、查询 40400；`is_public=0` → 40400。
4. 配额：请求数（分窗/日窗）与行数任一超限 → HTTP 429 + 42900 + `Retry-After`；匿名层 60/分/IP 不受影响。
5. 审计：四端点调用（含 401/429/40400 负例）均落 `acc_audit`，字段齐全；属主检索可用；90 天清理 cron 空跑/真删各一。
6. 路径收窄：新路径正例 200；同站点**另一未授权展示应用**的路径调同一接口 → 40400（边界 ① 闭合）；旧 `:slug/api/app/` 路径 → 404。
7. 游标分页：边拉边写场景 500 行全量抓取不重不漏；`sort` 自动 tiebreaker。
8. 一凭证一应用：Key A 调应用 B 的 appCode → 40400；配额与审计按凭证维度独立成账。
9. 数据层零改证明：对外四端点与开放层取数共用 `AppFacade` 调用链（代码走查 + 日志佐证），无第二条直读通道。
10. 回归：P14 开放层既有用例（授权正例/四类负例/限流）在新路径下全绿；`check:ai` 19/19、`smoke:ai` 7 用例全绿；双端 tsc/vue-tsc/ESLint 零错；生产构建通过。
