## 1. 背景与目标

P15 的 scope 模型为「表 / 字段 / 操作」三纵深，Q8 拍板时 **rowFilter 明确预留**（`acc_credential.scope` JSON 已有 `"rowFilter": null` 槽位）。本期启用该槽位：让凭证持有方只能读到满足条件的行子集（典型场景：只暴露 `status=published` 的行给外部系统）。

**零新表（槽位既有，零迁移）、零新端点、零新错误码、零新依赖、内部 AI 工具 43 与对外 MCP 工具 3 均不变。**

## 3. 规则（R147 起）

- **R147 语法与解析**：rowFilter 值必须是「表名 → 条件串数组」对象；条件串语法、算子集、值类型解析与 R104 请求 filter **同一解析器**。校验：表 ∈ scope.tables（否 50021）；条件引用字段 ∈ 该表 scope 字段口径（scope.fields 未配 = 该表全部已暴露字段可选）且字段在暴露开关内（否 50021）——**禁止用不可见字段做存在性探测**；算子合法、值类型可按字段定义解析（否 50021，errmsg 指明条目）。
- **R148 查询注入语义**：rowFilter 强制注入 WHERE（与请求方 filter 参数 **AND 取交集**）；条件冲突 → 空集正常返回空页（code 0，不报错）；游标分页 / 排序 / 配额 / 审计口径全部不变（rowFilter 是 WHERE 条件，与 keyset 正交）；字段投影收窄（R133）不受影响。**详情端点同样过 rowFilter**：行存在但不满足条件 → 40400（防探测口径一致）。
- **R149 运行期失效的保守判拒**：凭证签发后，rowFilter 引用的表/字段被下线或取消暴露 → 该表对此外凭证**整体判不可见（40400）**，不做「失效条目静默跳过」（跳过 = 结果集意外放大，安全回归；判拒 = 收窄，恢复暴露即自愈）。
- **R150 MCP 透明继承**：三件套经同一内核，rowFilter 自动生效；R143 工具集冻结不变，工具入参与描述不动。

## 5. 验收标准（7 条）

1. 创建/编辑凭证带非法 rowFilter（表不在 scope / 字段未暴露 / 算子非法 / 值类型不可解析）→ **50021** 且 errmsg 指明具体条目。
2. 生效收窄：scope `tables=[book]` + rowFilter `{"book":["status:eq:published"]}` → records 只回 published 行；叠加请求 filter 取交集正确。
3. 条件冲突：rowFilter `status:eq:published` + 请求 filter `status:eq:draft` → code 0 空页（不报错）。
4. rowFilter 下游标分页口径不变：单调排序键下边拉边写不重不漏；游标跨协议混用不受影响。
5. 详情端点：行存在但不满足 rowFilter → 40400；MCP `iplat_get_record` 同源同表现。
6. 运行期失效：取消暴露 rowFilter 引用字段后 → 该表 40400（判拒）；恢复暴露 → 自愈恢复可读。
7. 回归全绿：smoke:ext（41 + 新增组）、smoke:mcp 36/36、check:ai 19/19、smoke:ai 8/8、双端 tsc/ESLint 零错。
