## 3. 偏差清单

### 实现增强（认可 5 项）

- **E-1 405 + Allow: POST，守卫只挂 POST**：smoke 实测发现「守卫挂类级则未认证 GET 先撞 401、405 永不可达」，下移修复——比我基线更精确（我基线未考虑守卫挂载粒度对状态码可达性的影响，教训入角色卡）。
- **E-2 429 分支补回 X-RateLimit-\***：验收 #6 的严格执行，smoke 抓出即修。
- **E-3 审计检索按凭证过滤**：121 条配额探测流水会挤出默认窗口，脚本层修正。
- **E-4 tool-registry.ts 单点类型切断（TS2589）**：SDK 泛型在 TS 5.8 + zod 3.25 下必然炸（4GB 堆仍失败），`as unknown as` 收敛签名、运行时零差异、§32.11 留档、SDK 修复后可删。作为架构师**认可此工程处置**，不修订任何决策/规则；拆除条件已写明。
- **E-5（P15 销项顺带）C1 修复超出预期**：keyId 冲突无法端到端构造，改取「DB 侧 P2002 断言 + 应用侧 insertCredential 换新 keyId 自动重试一次」双证据——顺带根治了「唯一冲突暴露为 50000」的真缺陷。认可。

### 我方规格错误（认领 3 项，即 API §23.7 ①~③）

- **D-1 get_schema 返回形状**：基线写 `{ appCode, tables }`，REST data 段实为 `{ app, tables }`（§22.2），验收 #3 逐字段一致优先。认领——我发明了一个不存在的字段名。
- **D-2 50021 错误面归属**：基线把「字段通配 `*` → 50021」放进 MCP 工具错误面；实际 50021 是 scope 创建/编辑期校验（管理侧，§22.5），查询链无通配入口。认领。（P15 走查 C2 已由 smoke:ext「scope.fields.book=['*'] → 50021」在管理侧闭环，两处口径自洽。）
- **D-3 边界违例表现形态**：基线把 -32602 归为 JSON-RPC 协议层；实测 SDK 前置 zod 校验包成工具结果 `isError=true` + 文本含 `-32602`。认领——R144 措辞需按此实测口径修订（随追认落文档，不改号）。

### 实现错误（开补丁）

- **W11 = 遗留 38：对外附件流端点未纳入 scope 收窄**。`attachmentStream` 准入只看「引用索引 + 表·字段暴露」，不做 records/detail 同款的 `assertTableInScope` 交集——凭证 scope 只含 A 表时仍可流式读取 B 表引用的附件（fileId UUID 不可猜只是缓解，不是口径）。**定性：我方规格缺口（P15 规格未明示 files 端点的 scope 判定链，认领一半）+ 实现一致性缺陷。裁决：收窄**——scope 即授权边界是 P15 的安全不变量。补丁零新表/零新端点/零新错误码，详见随附单文档。**待用户确认后生效。**
