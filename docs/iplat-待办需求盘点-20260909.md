## 7. P4c 公开机制讨论结论（2026-09-09）

### 三概念分工（用户澄清定稿）

|      | 文件分享（P3 已有）                                 | 文件公开（P4c 新增）                        | 功能分享（远期）      |
| ---- | --------------------------------------------------- | ------------------------------------------- | --------------------- |
| 目的 | 让人下载拿走                                        | 在线消费，打开就能看/听/读                  | 别人克隆你的功能去用  |
| 载体 | cloud_share 随机 token（有效期/可停止/visit_count） | cloud_file.public_token（长期，取消即轮换） | 公开 token + 克隆动作 |
| 体验 | 访客分享页 → 下载                                   | 落地页 → 在线播放/查看 + 下载入口           | 克隆到我的云盘        |

分享与公开 UI 分入口、底层分存储，PRD 写明分工防混淆。

### 方案：A（原地公开 + token 直链），文件 + 文件夹一期同做

- `cloud_file` 加 `public_token`（唯一索引，仅显式设公开=1 的行生成；改名/移动不影响链接）+ `allow_listing`（仅文件夹有意义，默认 1）
- 取消公开 = token 轮换（重新公开 = 新 URL，防泄露 token 复活）
- 文件夹列表页：默认给，「设为公开」弹窗含「允许访客浏览文件列表」开关（默认开，可关；关闭后仅知道完整路径可访问）

### 文件类型支持：三层架构（用户核心问题「平台做还是用户自定义」的答案）

1. **通用落地页（平台做，本期核心）**：一个极简页面按类型分支——video/audio 原生 controls（自带倍速）、img、PDF 内嵌、其他 → 图标 + 名称；统一带下载按钮。前端独立公开路由 `/view/{token}`（照 T31 访客分享页先例：无布局、免登录）
2. **raw 裸流（平台做）**：`raw` 端点 = 用户自定义页面的供水管；用户在自己站点写任意体验页面直接引用（AI 可代写，P4b 能力）。规则写进 README.txt 契约 + PLATFORM-GUIDE，不专门开发
3. **文件夹列表页（平台做）**：`/view/d/{token}`

### 端点与纪律

- 端点：`/api/open/f/{token}/info`、`/f/{token}/raw`（inline + Range，视频拖进度条靠它，复用 T27 实现）、`/f/{token}/download`（attachment）、`/d/{token}`（列表数据）、`/d/{token}/{*path}`
- 复用：@Public、独立限流桶、统一 40400、三态上溯（父目录阻断 → 40400）、回收站文件 token 失效、no-cache + ETag（D28）、MIME 白名单 + text/plain 强制（R7）、审核门禁开关挂「设为公开」动作
- 错误码：40xxx 段自 40117 起；权限复用 `cloud:file:public`，不新增标识

### 已否决方案

- D（复制到公开文件夹）：双份配额、更新分叉、与 is_public 双语义并存、删除边界纠缠
- B（公开区移动）：打乱文件组织、移出回不去原位置
- C（强化分享机制）：与临时分享语义纠缠
