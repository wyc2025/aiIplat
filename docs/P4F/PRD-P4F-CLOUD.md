# PRD-P4F-CLOUD —— 云盘收尾清账：回收站自动清理 + 配额对账 + 历史小瑕疵打包

> 编号续接：决策 D58 起（D57 止）、规则 R58 起（R57 止）、任务 T66 起（T65 止）。本期预计**零新错误码、零新依赖**。
> 用户拍板（2026-09-13）：先清账再上 P5 AI 扩展；回收站自动清理本期做（N 天可配置）。

## 1. 背景与目标

P3~P4e 连续五期功能扩张后，云盘域攒下一批小而实的欠账。本期不引入新功能面，只做四件清账事 + 搭车文档补丁，把云盘域收拾到「可长期维护」状态。

**非目标**：分片上传/秒传/缩略图（P4 远期）；内容审核（上线前转 P0）；任何新依赖。

## 3. 规则

- **R58 清理范围**：凡 `deleted_at` 超期的 cloud_file 行一律清除——含普通文件/文件夹、删站后进入回收站的原站点根（还原窗口期即 N 天，与 R54 语义自洽）；头像旧行（parent_id=-1 且已软删）同样清理
- **R59 清理实现纪律**：复用既有「彻底删除」链（删物理文件 + 删行 + used 回退），禁止另写删除逻辑；分批执行（每批 ≤500 行），单批失败记录并继续下批，整体幂等可重入（下轮自然续扫）；cron 统一放 cloud 域 `*.task.ts`（照 P2a 月度额度重置先例）；每轮结束记运行日志（扫描数/清除数/失败数）
- **R60 对账公式**：`used 应然值 = Σ(未删除行 size) + Σ(回收站行 size) − Σ(已回退头像行 size)`；「已回退头像行」的识别口径以实现为准并在代码注释固化（parent_id=-1 且 deleted_at 非空）；诊断端点返回公式三项各自的行数与字节数 + 存储值 + 差额，便于人工定位
- **R61 修正授权**：修正端点仅 `cloud:admin:quota`，挂 @OperationLog（记旧值/新值/差额）；修正只写 `cloud_usage.used` 一个字段，不动任何文件行
- **R62 配额守卫放开**：用户管理页「配额」（云盘）按钮去掉 `v-if="row.username !== 'admin'"`，保留 `v-permission`——与 P4e 站点配额按钮修法对齐（同一根因的另一半）

## 4. 验收标准

1. 造一行 deleted_at 为 31 天前的回收站记录 → 跑一次清理任务（或临时调短 N 复现）→ 行与物理文件消失、used 回退正确、日志有统计
2. deleted_at 为 29 天前的记录不受影响（边界）；开关关闭时任务空跑
3. 含子树的文件夹超期 → 整棵子树物理清除无孤儿文件（物理目录核对）
4. 删站后的原站点根超期同样被清（R58 口径）
5. 对账诊断：返回公式三项明细 + 差额；对 admin 执行后能解释 22,751 字节差额的构成（或至少定位到公式哪一项）
6. 对账修正：差额存在时按钮出现，确认后 used = 重算值，操作日志有记录；无差额时按钮不出现
7. `download(row)` 下载后 Blob URL 正常回收且下载不再偶发失败（回归 P4d saveBlob 同款场景）
8. 任意 ElMessageBox 确认框按钮显示中文；guard.ts 正常导航不再刷 console
9. admin 行出现「配额」（云盘）按钮，UI 自调生效（复现 P4e 站点配额同款场景）
10. W1~W4 套用后：API.md 无 mine 残留、三处错误码总表收齐 30020/40118/40119、§1 日志行与实际一致
