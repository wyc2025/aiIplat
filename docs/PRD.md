# iplat —— 产品需求文档（PRD.md · 第一期：后台管理底座）

## 1. 项目概述

iplat 是一个可持续扩展的个人平台。第一期交付**后台管理底座**：登录认证、RBAC 权限体系、系统管理全套功能、布局框架，为后续业务模块提供统一的可扩展架子。

- 使用者：平台管理员（我自己）+ 未来平台的注册用户
- 访问方式：桌面浏览器，直接访问 web 地址（非 App 内嵌）
- 技术形态：pnpm monorepo，Vue3 前端 + NestJS 后端，细节见 ARCHITECTURE.md

## 2. 分期规划

| 阶段           | 模块                | 内容概述                                                             |
| -------------- | ------------------- | -------------------------------------------------------------------- |

| P2             | 云盘（cloud 域）    | 文件/文件夹管理、上传下载、配额；复用本期 sys_file 与 StorageService |

## 4. 核心业务流程

### 4.1 登录与权限链路

```
登录页输入账号密码 → 后端校验（失败计数，5 次锁 10 分钟）
→ 返回 accessToken(2h) + refreshToken(7d)
→ 前端调 /api/auth/userinfo 拿 用户+角色+权限标识+菜单树
→ 菜单树转动态路由注册，侧边栏渲染
→ 页面内按钮由 v-permission 按权限标识控制显隐
→ 后续请求自动带 token；401 时静默刷新，刷新失败回登录页
```

### 4.2 典型管理操作

- 新建用户：填基本信息 → 选择部门 → 分配角色 → 保存后可启禁用
- 角色授权：角色列表点"分配权限" → 弹出菜单权限树（含按钮级）→ 勾选保存，该角色下用户下次拉取 userinfo 生效
- 菜单维护：菜单树直接影响"用户登录后看到什么"，改菜单 = 改权限边界

## 5. 各页面功能细则

### F1 登录页

- 居中卡片：logo + 标题"iplat"、账号、密码、登录按钮
- 登录中按钮 loading；失败 ElMessage 提示后端 message；锁定时提示剩余锁定时间
- 背景简洁渐变即可，不做花哨设计

### F2 布局框架

- 侧边栏：按当前用户菜单树渲染，支持折叠（210px ↔ 64px），目录可展开收起
- 顶栏：折叠按钮 + 面包屑 + 右侧用户下拉（个人中心 / 退出登录）
- TabsBar：打开的页面形成标签页，可关闭单个/关闭其他/关闭全部，刷新后保留
- 设置抽屉：折叠状态持久化等界面设置（第一期只做折叠持久化）

### F3 Dashboard

- 统计卡片 4 张：用户总数、角色总数、今日登录次数、今日操作次数
- 近 7 天登录趋势折线图（ECharts，数据来自 sys_login_log 聚合接口）
- 快捷入口卡片：用户管理、角色管理、个人中心

### F4 用户管理

- 搜索区：用户名（模糊）、手机号、状态、时间范围；查询/重置
- 表格：头像、用户名、昵称、部门、角色（多个 tag 展示）、状态开关、最后登录时间、操作列
- 操作：新增、编辑、删除（确认框）、重置密码（重置为随机 8 位并弹窗展示一次）、分配角色（弹窗多选）
- admin 行禁用"删除/禁用/分配角色"按钮
- 新增/编辑表单校验：用户名必填 2~~50、邮箱格式、手机号格式、密码（新增时必填，8~~32 位含字母数字）

### F5 角色管理

- 表格：角色名、标识、排序、状态、创建时间、操作列
- 操作：新增、编辑、删除（被用户引用时禁止删除并提示）、分配权限（抽屉内菜单树，父子联动勾选，含按钮节点）
- admin 角色不可编辑、不可删除

### F6 菜单管理

- 树形表格（默认展开）：名称、图标、类型 tag（目录/菜单/按钮）、路由、组件路径、权限标识、排序、状态、操作列
- 操作：新增（可选择父级）、编辑、删除（有子级时禁止删除并提示）
- 表单字段随类型切换：目录/菜单显示路由与图标，菜单显示组件路径，按钮显示权限标识

### F7 部门管理

- 树形表格：名称、排序、状态、创建时间、操作列
- 删除校验：有子部门或有关联用户时禁止删除

### F8 字典管理

- 左右布局：左侧字典类型列表（增删改），右侧为选中类型下的字典数据表格（增删改）
- 类型删除校验：下有数据时禁止删除
- 内置字典：sys_common_status（启用/禁用）、sys_user_gender（男/女/未知）

### F9 / F10 日志

- 纯查询页：搜索区 + 表格 + 分页，无增删改
- 操作日志表格含：用户、模块、操作、请求方式、URL、IP、耗时、状态、时间；失败的可展开看错误信息

### F11 个人中心

- 左侧个人卡片（头像、昵称、角色、最后登录），右侧两个 Tab：基本信息（昵称/邮箱/手机/性别 修改）、修改密码（旧密码 + 新密码两次输入）
- 修改密码成功后强制重新登录

## 6. 关键业务规则

1. **超管保护**：admin 用户拥有全部权限，不可被禁用、删除、修改角色
2. **禁用即拒登**：status=0 的用户登录直接拒绝并提示；已登录 token 自然过期（本期不做实时踢出）
3. **删除前置校验**：角色被用户引用不可删；菜单有子级不可删；部门有子级或有关联用户不可删；字典类型下有数据不可删
4. **权限标识命名**：`域:模块:操作`，如 `system:user:create`，按钮菜单的 perms 字段必填
5. **初始数据**：seed 提供 admin/Admin@123 + 超级管理员/普通角色 + 系统管理全套菜单（见 ARCHITECTURE.md 第 5 节）
6. **密码策略**：8~32 位，必须含字母和数字；库中只存 bcrypt 哈希
7. **登录保护**：同一用户名连续失败 5 次锁定 10 分钟

## 7. 非功能需求

- 性能：首屏加载 < 3s；万级数据量下列表查询响应 < 500ms
- 安全：密码 bcrypt、DTO 全量校验、Prisma 参数化防注入、helmet、限流、CORS 白名单、JWT 过期机制
- 兼容：Chrome / Edge 最新两个大版本
- 显示：桌面优先，最小宽度 1280px，不做移动端适配
