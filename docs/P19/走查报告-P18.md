## 3. 偏差清单

### 实现增强（认可 5 项）

- **E-1 令牌路径实查凭证行**（§34.3）：令牌只证明「曾用正确 secret 换发」，授权事实（scope/吊销/到期）永远以凭证行为准——比我基线「Redis → principal」多一步 DB 回查，换来签发后收窄即时生效 + 吊销双保险。认可。
- **E-2 配额计入时机细化**（§34.7 ③）：通过客户端校验后才计配额——否则凭猜 keyId 即可刷空他人配额。比我 D142 的笼统表述更安全，认可并视为 D142 的精确化。
- **E-3 `UpdateCredentialDto` 显式接收 type 以报 40001**（§34.7 ①）：否则 ValidationPipe whitelist 静默剥离，用户以为改成功了。细节扎实，认可。
- **E-4 TokenStore 归属 credential/ 模块**：避免 ExtModule ↔ CredentialModule 循环依赖（§34.1）；基线未指定，实现合理，认可。
- **E-5 C2 证据抓出真缺陷**：`access/index.vue` 被 prettier 把多语句 `@click` 拆行 → vite 生产构建语法错误，而 **vue-tsc 与 ESLint 双双不报**（P17 交付遗留，本期修复并验证）。教训入角色卡：**前端验收资产必须含 vite build，vue-tsc 不足为凭**。
