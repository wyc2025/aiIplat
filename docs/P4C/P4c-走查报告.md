### 【低】W2.「公开链接」术语 P3/P4c 双含义未统一

P3 语境「公开链接」= 分享（cloud_share）：API §5.5 章节名、错误码 30009 文案「文件夹暂不支持创建公开链接」、配置项 `CLOUD_PUBLIC_SHARE_RATE_LIMIT` 注释「公开分享限流」；P4c 后「公开链接」= public_token。三概念分工是本期刚定的，同一术语指两个实体，后人必混淆。

**修复（纯文档）**：P3 语境统一改称「分享链接」——30009 文案改「文件夹暂不支持创建分享链接」、§5.5 章节名改「分享链接」、配置项名不动（改名动代码）但注释改「分享（cloud_share）限流」。

### 【低】W3. MIME 白名单三份分置的对照未写全

T46 偏差③承诺「T50 并入时写明各自口径与差异」，§16.2 只写了 pub-mime.ts 自身口径，三份（transfer 预览白名单 / site open/mime.ts / pub-mime.ts）的位置与场景对照未落。

**修复**：§16.2 MIME 行末补一句：「现状三份白名单分置：transfer 预览（P3，管理侧预览）/ site open/mime.ts（P4a，站点开放层）/ pub-mime.ts（P4c，公开端点）——域边界优先于复用，各自口径以代码为准」。

### 【低】W4. 限流硬编码决议痕迹缺失 + 「待补」行悬置

T46 偏差④写「T50 并入时如需配置化再议」，T50 未落结论——§16 没有任何一处说明「与 site 配置组口径不同系瘦版有意为之」，后人会误读为不一致缺陷；§4.7 配置表 `CLOUD_PUBLIC_SHARE_RATE_LIMIT`「待补」行自 P3 悬置，与 pub:rate 硬编码并存易误读。

**修复**：§16.2 限流处补「值硬编码 120/60（瘦版定值，与 site 配置组差异系有意为之；需调整时升配置组 CLOUD_PUB_STATIC_LIMIT / CLOUD_PUB_DATA_LIMIT）」；§4.7 该「待补」行删除或改注明确指向。

### 【观察 1】双「取消公开」语义并存（222 行案例已是真实后果）

旧 `set-public` 取消 = 落 2（显式阻断，站点语义）；新 `DELETE /cloud/file/:id/public` 取消 = 归 0（继承）。普通文件夹误用旧按钮会产生阻断态，其下 P4c 公开链接全部 40400（222 行实录）。§16.1 已写明分置理由（站点机制依赖），接受现状；**建议**（下阶段或随手，非本期）：旧按钮可见范围收敛到站点目录（或普通文件夹隐藏），暂不改代码则先把「曾取消公开（阻断）的目录下公开链接会拒访」落进 PLATFORM-GUIDE——222 行处置口径已含，欠落手册。

T47~T50 遗留的体验级复验项（落地页五分支渲染 / 下钻交互 / 拖拽面板与并发 / 解压流程），其中落地页分支已被 9-10 真实使用部分闭环。维持「随手覆盖」惯例；建议交接文档续补时汇总一份清单防永久漂移。
