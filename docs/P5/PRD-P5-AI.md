## 1. 背景与目标

AI 现有 11 个工具，能力边界：站点静态文件层 + 建站。缺口：站点之外的云盘不可见、站点 CMS 层（文章/栏目/标签，表驱动而非文件）完全不能操作、站点生命周期只有「建」没有「改/删」。同时工具数增长使 P2b 瑕疵④（轮次上限写死 3、上下文预算静态 25%）从「远期隐患」变成「本期必修」。

**目标**：AI 从「装修工人」升级为「平台运营助手」——会管云盘、会发文章、会管站点生命周期；引擎层预算动态化，为工具继续扩容铺路。

**非目标**：评论代审/代管（语义另立）；AI 删文章（用户拍板不给）；AI 上传二进制文件（AI 产出只有文本）；分词库（1 token≈1 字符口径延续）。

## 3. 规则

- **R63 工具纪律**：write 类全部确认卡 + summarize 结构化摘要；read 类自动执行；handler 只注入域门面；description 必须写清与近似工具的边界（`write_site_files` = 站点目录内 vs `write_cloud_file` = 云盘任意路径——25 个工具下防误选靠 description）
- **R64 云盘工具口径**：以用户云盘根为基点；路径规范化防穿越（空段/`..`/绝对路径拒绝）；read 复用站点读口径（文本白名单 + ≤64KB）；write 单文件 ≤256KB 文本、配额校验 30003、重名走 R4 自动"(1)"或覆盖确认（取覆盖：同路径旧文件软删进回收站，照 writeFileRaw 温和覆盖先例）；move 支持批量 + 目标目录自动 mkdir -p（逐段复用，照 writeFileRaw 纪律）；delete 仅软删
- **R65 文章工具口径**：columnId 归属校验 + ≤3 级（R6）；summary 空自动取正文前 100 字（复用既有口径）；coverPath 必须 media/ 前缀（40105）；tagIds 由 ensure 产出；字数后端统计落库（R14）
- **R66 删站确认卡**：summarize 必须返回三段影响 + 文章数统计（「将物理删除 N 篇文章/栏目/标签/评论，不可恢复；站点文件进回收站可还原；slug xxx 立即释放」）
- **R67 预算口径**：system prompt 恒完整、tools schema 恒完整，装不下时继续从最早历史消息丢弃；输出预留保持 25% 不变；实测占用每轮调用随过滤后工具子集动态计算（工具按权限过滤，各人不同）
- **R68 usage 估算扩展**：兜底估算 = 字符口径覆盖 messages + tools schema + tool 往返消息；结算幂等键不变

## 5. 验收标准

1. 「我云盘里有什么」→ list 真实结构；「把 A 移到 B」确认卡 → 云盘实际移动且管理页可见
2. write_cloud_file 确认后文件落盘 + used 记账正确；配额不足回喂 30003 不抛栈；同路径覆盖后旧文件在回收站
3. delete_cloud_files 确认后回收站可见、可还原
4. 「写篇文章归到技术栏目」→ 确认卡摘要含标题/栏目/标签/状态 → 确认后**草稿**出现在文章管理；「直接发布」→ 确认卡带「发布即公开可见」→ 发布后开放层可访问
5. update 已有文章确认后生效；工具清单中**不存在**删除文章工具
6. ensure 幂等：同名栏目/标签重复执行不产生重复行
7. delete_site 确认卡列三段影响 + 文章数；确认后走既有删站级联（回收站/缓存/slug 释放全对）
8. 权限过滤回归：无 `site:article:create` 权限的用户对应工具不下发（tools 字段过滤后为空时不携带）
9. 预算：构造长会话 + 25 工具场景，截取后 system+tools 完整、历史从最早丢弃、上游不报 context 超限；`ai.maxToolRounds` 改配置生效
10. write 确认链结算：usage 兜底估算含工具往返 tokens，金额合理（数量级校验）
11. PLATFORM-GUIDE 压缩改写后 ≤2000 字且覆盖新能力口径；description 边界抽查：`write_site_files` vs `write_cloud_file` 不混
