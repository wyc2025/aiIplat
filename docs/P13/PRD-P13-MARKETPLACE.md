# PRD-P13：应用市场（快照式发布 / admin 审核 / 复制）

> 状态：待实施。上游：P12 全链 + PATCH1/2 已闭环（D87~~D106 / R88~~R116 / T100~~T116）。
> 一句话：兑现原始愿景「应用发布到市场（经过审核），别人复制使用」——提交即物化结构快照，admin 人工审核后上架，复制者一键物化为自有应用。
> 编号：D107~~D111 / R117~~R123 / T117~~T123；**AI 工具 38→41（3 个写工具，D106 兑现）**。
>
> ⚠ **P14 演进标注（2026-09-30）**：市场快照按用户拍板⑥** bundle 化**——快照连「展示应用 + 授权关系」一起复制（出边闭包，复制时在接收方副本间重建授权，挂靠不随复制）。详见 PRD-P14 D117 / ARCHITECTURE §30.6：`submit_market_app` 确认卡扩展、`/api/market/:code/copy` 响应扩展 `displays[]`。本文档其余口径（快照冻结、演示数据、50013~50015）不变。

## 1. 背景与承接

- 原始愿景（用户 2026-09-22）：「他可以将自己的应用发布到应用市场（经过审核），这样别人就可以复制使用它的应用。」
- 本期兑现的延期债：**D106**（AI 写工具 publish/expose + 市场提交，用户 2026-09-26 拍板兑现，覆盖我方只读推荐）、**D103**（发布快照投影——审核面天然需要快照）。
- 持续挂账（不进本期）：站点内嵌应用数据的服务端语义（遗留 31，挂 P13+）、市场版本更新机制（D111 定 v1 不做）。

## 2. 决策

- **D107 快照式市场**：新域 `market`，主表 `market_listing`——提交那一刻物化**结构快照**（表/字段/关系/功能页全量），审核与复制都只针对快照，源应用后续变更不影响在架版本。快照**不含暴露配置**（is_exposed/is_public 不随快照走，副本全私有起步——隐私姿态）；**不含附件数据**（演示数据中的附件字段值强制置 null）。
- **D108 审核流 = admin 人工审核**（用户拍板）：状态机 `pending → approved | rejected → delisted`；审核动作挂 @OperationLog，拒绝必填 note；**每应用同时仅允许 1 个活跃条目**（pending 或 approved，重复提交 50013）。
- **D109 复制 = 默认仅结构 + 发布时可选「附演示数据」**（用户拍板）：演示数据 ≤100 行/表（超出 50015 拒绝提交，不静默截断）；复制物化经 DataService（红线），副本 `is_public=0` 起步、占复制者配额（50002 拦截）、`source_app_id` 记谱系。
- **D110 AI 写工具兑现 D106**（用户拍板）：新增 3 个 write 级工具（确认卡执行）——
  - `publish_data_app { appCode, isPublic }`：P12 自助公开总开关（开启走 R103，未过 50012，返回缺项引导模型先 expose）；
  - `expose_data_app { appCode, target: 'table'\|'field'\|'page', name, isExposed }`：粒度暴露开关（target=page 限 kind=display，否则 50004）；
  - `submit_market_app { appCode, withDemoData? }`：提交市场审核（50013/50015）。
- **D111 v1 边界**：无版本更新（下架后重新发布 = 新条目，更新机制挂账）；无在线实时预览（详情页 = 元数据卡片）；市场仅**登录用户**可见；被拒可重提（新条目，历史保留）。

## 3. 规则

- **R117 快照内容**：tables（含字段全量：类型/必填/默认/枚举/引用）+ rels（n:n 中间表由物化方重建）+ pages（admin 与 display 全含，schema 原样）；**不含**暴露三开关、不含数据（除非演示）。
- **R118 演示数据**：勾选 `withDemoData` 时提交物化各行（发布者数据，经 DataService 读取，≤100 行/表）；**attachment 类型字段值强制 null**（文件不可随复制迁移）；行数超限 → 50015（message 带表名与上限）。
- **R119 复制物化**：校验接收方配额 → 建 app_def（active，code 冲突自动 "(1)" 照 R93）→ 重建表/字段/关系（n:n 照 REL_FROM/TO_FIELD 重建中间表）→ 重建 pages → 演示数据逐行 `DataService.create`（独立事务，错误行跳过并计数）。物化全程经 AppFacade，market 域零跨域 import app 内部。
- **R120 市场可见性**：仅登录用户；列表 = approved 且未 delisted（分页，按上架时间倒序）；详情 = 元数据卡片（名称/描述/发布者昵称/表数/页数/含演示标记/上架时间/copy_count）。
- **R121 审核权限**：`market:review` 权限（admin 角色），seed 菜单「市场审核」；审核端点属 admin 命名空间；复制/提交/浏览 = 普通登录用户（无 @RequirePermission，同云盘属主口径）。
- **R122 AI 工具纪律**：3 工具全 write 级走确认卡（确认文案含后果：「公开后匿名可访问」/「提交后进入审核队列」）；`publish_data_app` 开启被 50012 拒时，模型按缺项先 `expose_data_app` 补齐再重试；工具 handler 全经 Facade（AppFacade/MarketFacade），ai 域零直读。
- **R123 手册余量纪律**：能力清单 931/1200（余 269，3 行 ~100 字内安全）；**合注 1978/2000 仅余 22 字**——新工具文案若需入合注，必须先精简既有条目腾挪（照 P11 手册预算腾挪先例），**超帽不允许**；通用版 996/1000 一字不动。

## 7. 验收标准

1. 提交：应用 → 市场（pending），快照与源应用即刻解耦（改源应用不影响条目）。
2. 50013：同应用重复提交被拦；被拒后可重提产生新条目。
3. 审核：admin 通过 → 列表可见、可复制；拒绝 → 带 note，市场不可见；全程 @OperationLog。
4. 演示数据：勾选提交 ≤100 行/表；超限 50015 带表名；复制后演示数据落库、附件字段为 null。
5. 复制：一键物化为接收方新应用（active），结构/关系/功能页与快照一致（含 n:n 中间表）；副本 is_public=0、不占发布者任何东西；配额满 50002。
6. AI 链（N 用例）：提示词「把应用 X 公开并提交市场」→ 断言 expose/publish/submit 工具按序出现（50012 缺项引导路径实测）。
7. 铁律：零新依赖；market 域零跨域 import（全 Facade）；写操作全确认卡；工具 41 个全归组。
8. 手册：能力清单 ≤1200、合注 ≤2000、通用版 ≤1000 全过 check:ai。
9. 前端：市场卡片流/详情/复制/发布弹窗/审核页五处可用，浏览器复验。
10. 回归：P12 全链零回归（46/46 抽测 + check:ai）；**P12 尾巴收尾清单（T122）全部销项**。
11. 工程：双端零错 + vite build + 文档回写完整。
12. 消耗如实登记（N 用例 + 联调）。

## 8. UI 要点

- 应用中心：seed「应用市场」节点（所有登录用户可见）；我的应用卡片「发布到市场」（未发布过才显示主按钮，已有活跃条目置灰提示）。
- 发布弹窗：withDemoData 勾选 + 逐表行数预览（超 100 行红字提示）；提交成功提示「等待审核」。
- 市场页：卡片流（名称/描述/发布者/表·页数/含演示标记）；详情抽屉 + 「复制此应用」按钮（复制成功跳转新应用）。
- 审核页（admin）：pending 列表（快照摘要：表/页清单），通过/拒绝（拒绝必填 note），已下架操作。
