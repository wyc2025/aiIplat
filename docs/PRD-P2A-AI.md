## 1. 需求背景与目标

为 iplat 引入 AI 助手能力，作为平台的第一个业务模块。P2a 交付"能对话、能计费、能管控"的完整闭环：

1. 用户侧：AI 对话（多会话、流式输出、切换模型）、查看套餐与积分用量、开通套餐
2. 管理侧：厂商/模型配置、套餐管理、给用户指派套餐、全量用量查询、在线用户查看与踢下线
3. 平台侧：按真实 token 用量扣积分、月度额度自动重置、四家大模型可切换

## 2. 范围

### 本期做

- ai 域后端：厂商/模型配置、会话/消息、SSE 流式对话、积分预检与结算、套餐订阅与月度重置
- system 域增量：在线用户跟踪（Redis）、在线用户列表接口、踢下线接口（复用 T10 全端下线机制）
- 前端：AI 对话页、我的用量页、开通套餐页、管理端四页（厂商模型/套餐/用量/在线用户）

### 本期不做（P2b 及以后）

- AI 工具调用（Function Calling）、确认卡片、自然语言操作业务数据
- AI 定时任务（"每天 8 点给我报表"这类）
- 真实支付、发票
- RAG / 文件问答（等云盘上线后）
- 多模态（图片/语音输入）
- 回复代码高亮（markdown 纯渲染即可）

## 4. 功能细则

### F1 AI 对话页（ai/chat/index）

- 布局：左侧会话列表（新建、重命名、删除、按更新时间倒序），右侧对话区
- 对话区：用户消息靠右、AI 消息靠左 markdown 渲染；流式输出逐字追加；流式期间显示"停止生成"按钮
- 顶部：模型选择器（下拉列出启用中的模型，按厂商分组显示厂商名 + 模型显示名）；切换模型作用于当前会话后续消息
- 输入框：底部多行输入，Enter 发送 / Shift+Enter 换行；发送后清空并禁用至流结束
- 状态处理：
  - 未开通套餐 → 全页空态 + "去开通套餐"跳转按钮（后端返回 20001 时也兜底提示）
  - 积分不足（20002）→ 消息区内提示 + 去开通链接
  - 上游模型失败（20005）→ 该条 AI 消息显示失败态 + 重试按钮
  - 40100 → 复用静默刷新后重试一次
- 会话创建与标题：点"新建会话"仅置本地态不调接口，首条消息随 /api/ai/chat（带 modelId）创建会话；后端取首条消息前 20 字自动生成标题，前端在 done 事件后刷新会话列表展示；用户可改

### F2 开通套餐页（ai/plan/index）

- 卡片式展示启用中的套餐：名称、月积分额度、价格、说明
- 当前生效套餐标记"当前套餐"；点击"开通/切换"→ 确认弹窗（说明本期无真实支付、额度立即生效、次月自动重置）→ 确认后生效
- 已有套餐时切换：立即替换，额度按新套餐重置（本期不做按比例折算）

### F3 我的用量页（ai/usage/index）

- 顶部卡片：当前套餐、本周期起止、总额度 / 已用 / 剩余（带进度条）
- 下方用量明细表（ProTable）：时间、模型、输入 tokens、输出 tokens、扣减积分、会话标题；按时间倒序；可按模型筛选

### F4 厂商模型管理（ai/provider/index，admin）

- 左右布局（复用字典页模式）：左侧厂商列表（新增/编辑/启禁用），右侧该厂商的模型表格
- 厂商字段：名称、标识 code（deepseek/kimi/qwen/zhipu）、baseUrl、apiKey（掩码回显，编辑时可改）、状态、排序
- 模型字段：显示名、模型名（API 用）、输入单价（积分/千 tokens）、输出单价（积分/千 tokens）、上下文长度、是否支持工具调用（本期存值备用）、状态、排序

### F5 套餐管理（ai/admin/plan/index，admin）

- 套餐 CRUD：名称、标识、月积分额度、价格、说明、状态、排序
- 操作"指派用户"：弹窗选择用户（搜索下拉）→ 确认后该用户套餐立即生效
- 删除校验：套餐下有生效中的订阅时禁止删除

### F6 用量明细（ai/admin/usage/index，admin）

- 全量用量查询：按用户（用户名模糊）、模型、时间范围筛选；表格字段同 F3 明细 + 用户名
- 顶部汇总卡片：筛选范围内的总 tokens、总积分

### F7 在线用户（system/online/index，admin）

- ProTable 列表：用户名、昵称、登录 IP、登录时间、最后活跃时间
- 操作"踢下线"：确认框 → 调用踢下线接口 → 列表刷新；admin 行不显示该按钮
- 数据来自 Redis 在线会话（30 分钟滑动过期），**仅作实时观察，不作审计依据**

## 5. 关键业务规则

1. **积分 = 平台内部计量单位**，本质是钱：`扣减积分 = ceil(输入tokens/1000 × 输入单价 + 输出tokens/1000 × 输出单价)`，单价为每个模型在 ai_model 表配置的积分/千 tokens
2. **扣费流程**：调用前预检（有生效套餐且剩余积分 > 0，否则 20001/20002 直接拒）→ 调上游 → 流内容全部下发后、done 事件前完成结算（写 ai_usage_log + 扣额度，以 message_id 幂等，重复结算不生效），done 携带结算后的真实 remainingCredits。**允许在途一次超扣**：结算后 used_credits 可略超 total_credits，展示层剩余按 max(0, 总额-已用) 计。上游未返回 usage 时按字符数保守估算并在 ai_usage_log 标记 estimated=1
3. **额度周期**：ai_user_plan 记录 cycle_start/cycle_end（开通日起一个自然月）。重置采用**懒重置 + cron 兜底**：预检时发现 cycle_end 已过即就地清零 used_credits 并滚动周期（避免过期到 cron 之间的空窗期误拒）；每日 00:30 cron 扫描兜底；切换套餐立即按新套餐重置
4. **套餐校验是业务校验不是 RBAC**：聊天等用户侧接口不挂 @RequirePermission，由 CreditService 预检兜底
5. **踢下线复用既有机制**：写 `user:pwd:changed:{userId}` 时间戳 + 清该用户全部 refresh token + 清权限缓存（与改密码全端下线同一套，被踢用户下一个请求即 40100 回登录页）
6. **在线判定**：JwtAuthGuard 校验通过时刷新 `online:{userId}`（hash：username/nickname/ip/loginAt/lastActiveAt），TTL 30 分钟滑动过期；登出时主动删除
7. **SSE 接口是统一响应格式的唯一例外**：前置校验失败走正常 JSON 错误码；进入流式后错误以 `type:"error"` 事件下发；详见 API.md
8. **AI 域错误码段：20xxx**（system 已占用 101xx~106xx）：20001 未开通套餐、20002 积分不足、20003 模型不可用/已停用、20004 会话不存在或无权访问、20005 上游模型调用失败、20006 消息内容超出模型上下文长度、20007 上一段对话进行中（并发流限制）
9. **限流**：聊天接口 20 次/分/用户，其余接口走全局限流
10. **密钥安全**：apiKey 仅在数据库保存，任何接口不得返回完整值；日志禁止打印 apiKey

## 6. 非功能需求

- SSE 首 token 延迟取决于上游，平台不额外增加 > 500ms 开销
- 流式期间断网/关页：后端检测到连接断开即中断上游调用，已产生 tokens 按实际结算
- 上下文管理：发送给上游的消息按模型上下文长度从最新往回截取，超长老消息丢弃（不做摘要，P2b 再议）
- 并发：同一用户同时只允许 1 条进行中的流式对话（前端禁用 + 后端校验）

## 7. 验收标准

- [ ] seed 后四家厂商配置就位（apiKey 为空待填），填入有效 key 即可对话
- [ ] 未开通套餐用户发消息返回 20001，前端引导去开通页
- [ ] 开通套餐后对话正常：流式逐字输出、markdown 渲染、可停止、可切换模型
- [ ] 每条消息结算后：ai_usage_log 新增一条（tokens 与上游 usage 一致）、额度扣减正确、我的用量页可见
- [ ] 积分扣到 0 后再发消息返回 20002
- [ ] 同一用户在前一条流式未结束时再发消息返回 20007；停止生成后已产生 tokens 照常结算
- [ ] 手动把 cycle_end 改到昨天，等 cron（或手动触发）后额度重置
- [ ] 管理端：厂商/模型/套餐 CRUD 正常，apiKey 掩码展示；指派套餐后用户立即生效
- [ ] 在线用户列表能看到当前登录用户；踢下线后被踢用户下一个请求即回登录页
- [ ] 权限：common 角色看不到 AI 管理菜单，直接调管理接口返回 40300
- [ ] 新会话首条消息后自动生成标题；会话重命名/删除正常
